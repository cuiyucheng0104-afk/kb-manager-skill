# 交付就绪审计 · 各维度探针清单

对每个维度,尽量**实测**(调用运行中的服务/在目标环境跑),读代码只用于定位与佐证。每条给结论 ready / needs-config / blocked + 证据。

## 维度 1 · 功能真实性(真接通 vs 样板/占位)

判断每个关键能力是"真接了引擎"还是"样板/占位/静默回落":

- 实际调用运行中的端点,看**真实返回**(真流式?真数据?真结构化?还是空/占位/error)。
- 追链路到底层:是否真接了模型(vs stub)、真检索(vs 空召回)、真库(vs 内存/mock)、真存储。
- 静默回落陷阱:很多系统在依赖缺失时**不报错**,而是回落到低质实现(哈希向量、stub 模型、内存表)——读代码看不出,只有实测能暴露。看关键路径有没有 `try/except → 回落` 或 `if not configured: return stub`。
- 边界:无输入/空数据/超大输入时是崩、还是优雅降级、还是假装成功。

## 维度 2 · 安全与登录/鉴权形态

单机自用可暂缓,联网/多人/对外**必办**:

- **登录是否真门**:账号密码是否真校验,还是"假登录"(空输入也进 / 只弹提示就跳转)。有没有用户表、有没有换取凭据的流程。
- **联调后门是否随包上线**:如 `ALLOW_DEV_AUTH=true`、`dev:` 免签名 token、`DEBUG=true`。实测:伪造一个凭据(填个猜得到的租户名)能不能拿到数据。
- **默认弱口令**:`admin/admin`、`zt-admin`、示例密钥有没有被换掉。
- **绑定地址**:服务绑 `0.0.0.0`(局域网可达)还是 `127.0.0.1`(仅本机)。
- **身份是否可伪造**:租户/角色/权限是不是"token 自报即信任"、服务端不二次校验。
- **生产鉴权是否真被使用**:JWT/SSO 代码就绪 ≠ 启用;前端有没有硬编码联调 token、根本不走真登录。

## 维度 3 · 干净目标机首次启动

CI 只证明"能打包",不证明"客户机能起":

- **真机监督首启**:在一台干净的目标机(对的 OS、可能离线、可能有杀软)实际装一遍、双击起一遍,走到可用界面。
- **就绪门槛**:启动器是否只看某一个服务健康就开窗?若别的依赖(向量库/后端)没起也放行 → "能进但啥都不出"。健康检查应覆盖全部关键依赖。
- **建库/迁移/灌种健壮性**:是否幂等?中途失败会不会留半成品(库文件已建但种子没灌 → 下次靠"文件存在"跳过 → 配置永远空且无提示)?失败应回滚 + 非零退出拦启动。
- **打包完整性**:自带的二进制/模型/依赖是否齐(常漏:某个 pip 包、某二进制的配套 config 目录、离线模型缓存布局)。改依赖清单时,打包脚本的清单要同步改。
- **签名/信任**:未签名安装包 + 拉起本地服务,可能被 SmartScreen/杀软拦。

## 维度 4 · 配置与数据前提(没配就用不了)

列全"要先满足什么才有价值",否则用户以为"坏了":

- **模型/密钥**:大模型是否在包内?不在的话装完必须配(本地推理服务或云 API key)。模型掉线时的表现(该功能崩?还是写一句"调用失败"污染产出?)。
- **模型型号对齐**:向量模型维度必须与向量库 collection 对齐;装错型号会静默回落 → 召回全空。把型号钉死并校验已安装。
- **数据前提**:很多能力(检索/报告/核查)依赖"资料先导入并索引"。无数据不报错但产出空壳 —— 必须先跑通"导入→清洗→向量化→入库"。
- **业务配置**:套型/清单/规则/许可证等 seed 是否齐;新客户是否要补配。
- **配置漂移**:多份启动脚本/文档指向不同端口/模型/依赖 → 统一到一份文档化配置,否则"有时好有时坏"。

## 结论与定位

- 每维度给 **ready / needs-config / blocked**;整体结论取决于**当前定位**:
  - *客户先自用 / 内部试用(单机、一人一机、离线)*:安全类 blocker 风险可控,可先用、并行补。
  - *正式对外 / 联网 / 多人*:安全与首启类 blocker 必须先清。
- 产出**「正式对外交付前必办清单」**:P0(阻断)在前,P1(前提/预期管理)在后,每条可执行、可验收。
