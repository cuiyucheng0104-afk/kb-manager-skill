# 交付就绪审计(Delivery Readiness Audit)

## 核心原则

**CI 绿 / 单测过 / 构建成功 ≠ 可交付。** 三者只证明"能打包、测到的路径没红",都**不**证明真机端到端能跑、安全形态可交付、以及"没配就用不了"的前提已满足。

可交付性靠**实测**判定(实际运行、真实调用运行中的服务,看真实返回),按维度给 **ready / needs-config / blocked** 三级结论 —— 不是二元的"能 / 不能"。

## 铁律 + 红旗(STOP)

**不得**仅凭构建/测试信号就宣布"可交付 / 完成 / 上线就绪"。出现下列念头即停,先跑本审计:

- "windows-test 绿了 + 安装包能构建 → 可以交付了"
- "单测全过 → 功能能用了"
- "读了代码,看着是接通的 → 算它能用"
- "CI 三绿 → 真机肯定能起"
- "用户在等好消息,先说能交付吧"

> 真实教训:曾凭"CI 三绿 + 安装包构建成功"就写下"两个版本都是可交付状态了";一次实测审计才暴露**登录鉴权裸奔**(伪造 token 即拿全部数据)这个 blocker,同时也才确认原以为"没验证"的核心功能其实真能用。**两个方向都被 CI 绿骗了。**

## 四个维度(逐一实测)

对每个关键能力/形态,实测后给 ready / needs-config / blocked + 证据 + 阻碍清单:

1. **功能真实性** — 每个关键能力是**真接通**(真模型/DB/服务/RAG),还是样板/占位/静默回落?**实际调用运行中的服务看真实返回**,并追代码到模型/存储层确认,而非读代码猜。
2. **安全与登录形态** — 登录是否真门(还是假登录直接进)?有无联调后门随包上线(如 dev 免签名 token)?默认弱口令、服务绑 `0.0.0.0`、租户/角色是否被 token 自报即信任?伪造凭据实测能否拿数据?
3. **干净目标机首启** — 在**全新机器**上真能装起来跑通吗(不是"CI 能打包")?就绪门槛是否够(某依赖没起却照样进主界面 = "能进但啥都不出")?建库/迁移/灌种失败是否会毒化(半成品留着、下次跳过)?
4. **配置与数据前提** — 哪些是"没配就用不了":大模型/密钥、向量模型型号对齐、必须先导入并索引的数据、许可证。这些不满足时用户会以为"坏了"。

详细每维度的探针清单见 [references/audit-dimensions.md](references/audit-dimensions.md)。

## 方法

- **实测优先**:`curl`/调用运行中的服务、看真实返回;追到它是否真接了模型/DB/RAG/存储(还是占位/静默回落成哈希/stub)。读代码只用于定位,不用于下结论。
- **对抗式怀疑**:默认"它可能是样板",只有实际跑出真实结果才判 ready。
- **分维度并行**:能力多时用多 agent 各审一维,每个 agent 实测 + 结构化结论。可复用的编排模板见 [scripts/readiness-audit.workflow.js](scripts/readiness-audit.workflow.js)。

## 输出格式

一张表 + 一份清单:

| 维度/能力 | 结论 | 实测能用的 | 交付前必办阻碍 | 证据 |
|---|---|---|---|---|
| … | ready / needs-config / blocked | … | … | curl 结果 / file:line |

外加**「正式对外交付前必办清单」**(P0 阻断项在前),并明确当前定位(如:客户先自用 vs 正式对外)——不同定位下同一 blocker 的紧迫度不同。

## 常见合理化(都要拦下)

| 借口 | 现实 |
|---|---|
| "CI 绿 / 单测过 = 能交付" | 只证明测到的路径没红;真机端到端、安全形态、配置前提都没测到 |
| "构建/安装包成功 = 真机能起" | 只证明能打包;qdrant/服务在客户机真起没起、杀软拦不拦,未验证 |
| "读代码看着接通了 = 能用" | 静默回落(hash embedder / stub LLM)读代码看不出;必须实际调用看真实返回 |
| "用户想听能交付,先给个乐观结论" | 诚实比让人安心重要;下结论要基于实测,不迎合期待 |
| "功能测试过了 = 完成" | 功能测过 ≠ 前提满足(没导数据 / 没配模型时功能空转) |

## 常见错误

- 只报"能用的",不列"没配就不能用的前提"→ 用户拿到手发现是空壳。
- 二元结论("能/不能")→ 丢掉了 needs-config 这档最有用的信息。
- 把安全形态漏掉 → 功能都对,却带着后门/裸奔上线。
- 只在开发机验证 → 干净目标机首启的断点全没测到。
